# Manual test on your reference MP4

The first supplied 23.125 s reference was processed on 2026-10-25. Extraction, local inference,
sample-exact clipping and fresh/repeated MCP calls passed. Independent listening annotations,
and named-SFX accuracy remain pending. The user later relayed a successful Dodik initiation,
report interpretation and cached repeat; matching local artifacts were verified. Keep media in
`private-media/` (gitignored) or outside the repository. The evaluation procedure follows.

1. Listen and mark speech starts/ends, audible effects, strong attacks and musical accents.
   Record names as tentative where the sound is ambiguous. Mark abrupt visual changes separately.
2. Analyze without models, then with prepared local YAMNet and multilingual Whisper. Use a new
   library so comparisons do not silently reuse older results.
3. For each manual mark, inspect the reported interval and WAV excerpt. Match attacks within
   100 ms; evaluate coarse YAMNet patches separately rather than assigning them sample accuracy.
4. Record true/false/missed attack candidates and labels; do not score a generic `unknown` attack
   as successful named-SFX classification. Check speech onset and transcript against listening.
5. Compare rhythm candidates with music manually; log half/double tempo failures. Inspect whether
   frame-change coincidences help explain editing without inventing visual action semantics.
6. Let a compatible agent read the report and make a supported editing explanation. Then test
   Dodik's actual initiation/report-return workflow as described in `dot-integration.md`.

Manual annotation template: [examples/manual-annotations.template.json](../examples/manual-annotations.template.json).
For each failed case, record the source hash, model hashes/options, expected time/label, observed
time/label and concrete symptom. Candidate improvements: calibrated CLAP descriptions, better
onset thresholding on mixtures, source separation evaluated for SFX, or a labeled motion dataset.
Do not publish the clip or excerpts without confirmed rights.

## Offline listening worksheet

`scripts/build_listening_review.py` builds a standalone local page using existing reports,
matching MP4 files and their exported WAV clips. It verifies source hashes and embeds the media;
the page makes no network requests. The generated page contains private media, so keep it in
`validation-output/` or another private folder, and do not publish it.

Create a JSON manifest with an array of objects containing `title`, `report` and `video`.
Paths are relative to the manifest. Run:

```powershell
.\.venv\Scripts\python.exe scripts\build_listening_review.py manifest.json --output validation-output\listening-review\index.html
```

Open the generated HTML in a browser. Listen to each full video and add missed significant
sounds at the current video timestamp. Then classify candidate clips and mark their editing
usefulness. The initial up-to-12 clips per source sample strong, scene-adjacent and time-spread
candidates, avoiding excerpt pairs with over 80% overlap of the shorter window. This is window
diversity, not semantic deduplication; closely spaced distinct effects remain in the full list.
The deliberately selected convenience sample is not an unbiased quality metric.
All reported attack clips are also available. Source-level full-review checkboxes default to
false; no listening judgments are generated by the tool.

Annotations autosave in browser storage where available. Use **Сохранить отметки** to download
`dotears-listening-annotations.json`; **Загрузить отметки** restores an exported file after
checking its schema, source hashes and event IDs. The export contains annotations and report
provenance, without embedded media, in the `dotears.listening-review/1` format. It is a separate
worksheet format from `examples/manual-annotations.template.json`. Changing controls does not
write to the original reports. Full recall/false-positive measurements still require a full
listening pass, all candidate reviews, and explicit matching of manual marks to predictions.

## Clean SFX labeling worksheet

`scripts/build_sfx_labeling.py` and `scripts/sfx_labeling.html` build a separate offline
audio-only worksheet from a `dotears.sfx-review-manifest/1` manifest. All previews are embedded
WAVs; SHA-256 checks bind the audio to the export. The stable dataset ID includes the ordered
sample identities, preview hashes, family groups and label-set version. Source filenames,
candidate selection pools and model predictions are not displayed beside the audio.

```powershell
.\.venv\Scripts\python.exe scripts\build_sfx_labeling.py validation-output\sfx-labeling-2026-10-27\manifest.json --output validation-output\sfx-labeling-2026-10-27\index.html
```

The first prepared set contains 30 unreviewed CC0 examples, selected as candidates for whoosh,
notification-like chime and UI click. Sources are Kenney Interface Sounds and three OpenGameArt
authors. Full sources, file hashes, conservative family groups, preview transforms and an audit
of all decoded PCM are retained in gitignored `validation-output/sfx-labeling-2026-10-27/`.
Previews preserve the entire decoded sound and original channel count, at 48 kHz/16 bit, with
150 ms leading and 250 ms trailing silence and no gain adjustment. Those selection pools are
not human labels. Other/uncertain answers are available and no category defaults are supplied.

Export **Сохранить разметку** downloads `dotears-sfx-labels.json` with schema
`dotears.sfx-labels/1`. It contains every sample's source/preview hashes and family ID, nullable
label/confidence, multiple-sound flag, notes and playback-start count; it contains no media.
Uncertain answers use low confidence and must not be treated as confirmed semantic labels.
Partial exports remain partial. Validated import restores a complete snapshot; a mismatched
dataset, hash or invalid annotation is rejected before modifying the current state. Browser
storage provides resumable autosave where available, with explicit fallback to JSON export.

This format is distinct from the previous video-reference listening worksheet. Preserve whole
recording/variant families when designing development and held-out splits; do not claim
precision/recall from this convenience set or from file names. Music/speech negatives and
controlled mixtures require their own evaluation stage. Two such local experiments were run
on 2026-10-28; see `docs/sfx.md` for failures and limits.

The second prepared worksheet, in gitignored
`validation-output/sfx-reference-eval-2026-10-28/index.html`, has eight new samples from qubodup
and StarNinjas CC0 packs. It preserves decoded mono PCM with the same added silence and no
gain change. No first-set samples repeat. The manifest's optional `export_filename` selects
`dotears-sfx-round2-labels.json`; the dataset ID is `231825dd8df68bf1c877ba38`. The original
30-example page, saved answers and default export filename remain intact.
