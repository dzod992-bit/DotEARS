# Architecture and report contract

```text
local file / optional public URL
  -> acquisition (temporary download worker with limits)
  -> FFprobe (size/duration/stream validation)
  -> SHA-256 + options + runtime/model provenance
  -> per-reference lock, staging folder
  -> native PCM WAV + analysis WAV + original-track remux
  -> Librosa attacks / rhythm / energy
  -> optional local YAMNet and local faster-whisper (sequential)
  -> native PCM clips
  -> optional FFmpeg scene changes and timestamp matching
  -> JSON + Markdown -> atomic final reference folder
```

`core.analyze` is independent of any LLM or agent. CLI calls it directly; MCP launches that CLI
in a serialized child process to isolate native Windows libraries and release model memory.
MCP workers use a separate null stdin, explicit CPU thread bounds and a 600 s job timeout.
No HTTP listener or network model is used. URL downloads and explicit model preparation are the only intended
network operations. Local SavedModels are executable model artifacts: use trusted official weights.

`AnalysisOptions` controls sample rate/channels, duration/size limits, clip margins, event cap,
visual threshold/tolerance, per-media-operation timeout, local model paths and CPU threads.
The minimal core imports no TensorFlow or Whisper at startup. Models load sequentially on demand;
their weights remain on disk. In-process reuse of loaded neural models is not implemented yet.

## JSON 0.1

See [schema](../schemas/report-0.1.json) and the generated [example](../examples/report.synthetic.json).
Schema version changes when field meanings change; engine version changes when implementation
behavior changes. Consumers should inspect both. There is no API call hidden behind a field.

- All event/energy/beat/visual times use seconds relative to the container start. Decoded audio
  can begin later: `audio.timeline_offset_seconds` records that offset. Clip times use the same
  timeline; the standalone `clip` command instead expects times within its WAV input.
- `category=audio_attack`, `label=unknown` is a DSP candidate, with a relative strength score.
  It is not a sound effect classification. Music/voice may cause the same observation.
- YAMNet uses original AudioSet labels, its 0.48 s patch hop and overlapping 0.975 s waveform
  support. Bounds describe patch support, not precisely annotated event boundaries.
- `confidence=null` is deliberate. `score_kind` explains each score. Neither model scores nor
  normalized onset strengths have been calibrated as probabilities.
- `has_music`/`has_speech=null` means not established. YAMNet booleans describe detection above
  the selected threshold; false is not proof of absence. A nonempty transcript sets speech true.
- `clip_path`, `native_path`, `analysis_path`, `original_path` are relative to the directory
  containing `report_path`. The source URL/path and model paths may contain private metadata.
- `mixture_status` always identifies an excerpt of the mixed track. `overlap` lists overlapping
  classifier categories if available, otherwise `unknown`; it never promises isolated audio.
- Scene events indicate abrupt frame change. Sync candidates report proximity only. The toolkit
  cannot infer a title scaling, an intended transition, or a causal relationship.
- Model/ASR status distinguishes not requested from completed. Explicitly requested broken
  models fail the analysis instead of silently returning a success without them.
- Tags, visual descriptions, editing role and Remotion notes are intentionally empty until
  an agent reviews the evidence. No arbitrary interpretation is generated by the DSP engine.
- An agent can save its reviewed observations in a separate `reference-review.json` sidecar
  beside the report. It should record evidence, hypotheses, listening status and reuse rights.
  This preserves the generated report; the core does not automatically generate or merge reviews.

## Library and reproducibility

The reference ID hashes input bytes, validated options, engine/runtime versions and model content
hashes. A changed model/options/version gets a new entry. Media title is not a filename component.
An identical local file under a new name reuses the first entry and returns `request_source` in the
response, preserving the saved original provenance. URLs are downloaded before content hashing.

Staging is created in the library filesystem; a lock prevents concurrent writes for the same ID.
On Windows, 0.1.1 uses random exclusive directories that inherit the parent's existing access.
It avoids `mkdir(mode=0o700)`, whose owner-only Windows ACL can exclude a restricted agent
token even within an authorized workspace. POSIX keeps standard private temporary directories.
Only a fully written reference is renamed into place. Errors remove staging and temporary downloads.
A process crash can leave a lock or staging folder; inspect it before manual removal. Cache hits
check that referenced files exist; they do not rehash all generated clips or repair tampering.
The content hash has 96 bits in directory names; full source/model SHA-256 values remain in JSON.

The engine records per-stage elapsed time and media artifact bytes. Its total excludes final
report serialization/rename and cached reports retain original timings. Peak memory is explicitly
unmeasured there. The benchmark samples process-tree RSS and total wall time in a fresh process.
